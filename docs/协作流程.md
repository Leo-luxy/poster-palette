# 协作流程：每人一条分支，直接 push

> 目标：B、C、D 各自在自己的分支上干活，随时 push 到 GitHub；A 只负责最后点一下合并。
> 全程不需要背命令，需要点的地方都写成了「点哪里」。

---

## 0. 一句话版本

```
main          只读，谁都不能直接推（包括 A，除了 A 用管理员权限）
feat/b        B 的分支
feat/c        C 的分支
feat/d        D 的分支
```

每个人在自己分支上 commit + push，推完在网页上点一个按钮提 PR，A 点 Merge。
**分支之间不会互相影响**，因为四个人改的是不同文件（见第 4 节）。

---

## 1. 为什么不能一起往 main 推

四个人的改动如果都直接进 main，会碰到两件事：

1. **谁后推谁失败**。Git 要求你的本地 main 包含远端 main 的全部提交，否则 push 会被拒
   （`Updates were rejected because the remote contains work that you do not have locally`）。
   要解决就得先 merge 再推，这一步对不熟 Git 的人最容易崩。
2. **崩了没法回退**。一个坏提交进了 main，所有人都得跟着处理。

分支把这两个问题都消掉了：每人一个平行副本，推自己的分支永远不会被拒；
main 只在「确认能用」的时候前进一格。

## 2. 一次性准备（A 做，10 分钟）

### 2.1 把三个人加成协作者

网页进仓库 → **Settings** → 左侧 **Collaborators** → **Add people** → 输 GitHub 用户名 → 选 **Add**。
三人会收到邮件邀请，**必须点邮件里的 Accept invitation**，否则没有推送权限。

> 免费账号的私有仓库最多 3 个协作者，公开仓库不限。本仓库是公开的，不受限。

### 2.2 三条分支（已经建好了）

```bash
git push origin main:feat/b main:feat/c main:feat/d
```

现在远端已经有 `feat/b`、`feat/c`、`feat/d` 三条分支，起点都是当前 main。

### 2.3 保护 main（已经配好了）

规则：**任何人不能直接 push 到 main，也不能强推、不能删 main；改动必须走 Pull Request，且需要 1 个批准。**

效果是：队友在自己的分支上推得再乱，也污染不到 main；A 依然是唯一能把东西放进 main 的人
（A 是仓库管理员，保留了直接推的权限，方便随时补数据）。

队友如果手滑选了 main 分支去提交，push 会被拒，报错大意是
`protected branch hook declined`——**这是设计如此，不是出 bug**，切回自己的分支重推即可。

## 3. 队友要做的，一共五步

### 第 1 步：接受邀请（1 分钟）

打开邮件 → **Accept invitation**。或者直接打开仓库链接，页面顶部会有绿色按钮。

没收到邮件：让对方把仓库链接发你，打开后页面顶部会提示「You've been invited」，点 **Accept**。

### 第 2 步：装 GitHub Desktop 并登录（3 分钟）

下载 <https://desktop.github.com> → 安装 → 打开 → **Sign in to GitHub.com** → 浏览器里授权。

> 装完第一次打开会让你填名字和邮箱，随便填真实姓名 + 常用邮箱即可，只影响提交记录里显示谁。

### 第 3 步：把仓库拉到本地（8–12 分钟）

**File → Clone repository → URL 标签页**，粘贴：

```
https://github.com/Leo-luxy/poster-palette.git
```

**Local path** 选一个你找得到的位置（比如 `~/Documents/poster-palette`），点 **Clone**。

⚠️ 仓库带 14,657 张海报（716 MB），所以这一步慢，**8–12 分钟是正常的**，进度条卡住别关。
克隆完只有这一次慢，以后每次同步只拉改动的几十 KB。

### 第 4 步：切到自己的分支

顶部中间有个 **Current Branch** 按钮 → 列表里选 `feat/b`（或 `feat/c`、`feat/d`）。

切完按钮上显示的应该是 `feat/b` 而不是 `main`。**每次开始干活前先确认这一行**，
这是唯一一个「选错了会白干」的地方。

### 第 5 步：干活 → 提交 → 推送

1. 在文件夹里正常做事（跑 Python、存图、写 md），文件改动会自动出现在 Desktop 左侧 **Changes**
2. 左下角 **Summary** 写一句人话，比如 `图1 色相分布初稿`
3. 点 **Commit to feat/b**
4. 点顶部 **Push origin**

推完就完事了。想改就再重复 2–4，**推多少次都行**，不会覆盖别人的东西。

### 第 6 步（可选）：提 PR

push 完网页上会出现一条黄条 **Compare & pull request**，点它 → 标题写一句 → **Create pull request**。

不想点也行，A 会看到你的分支更新了，替你开。

## 4. 唯一要守的规矩：只改自己的文件

四个人同时改同一个文件，Git 才会冲突。所以按文件分工，**各改各的，物理上不可能撞**：

| 人 | 只改这些 | 绝对别碰 |
| --- | --- | --- |
| **B** | `figures/fig_q1_*.png`、`outputs/b/` | `data/`、`scripts/`、别人的图 |
| **C** | `figures/fig_q2_*.png`、`figures/fig_q4_*.png`、`outputs/c/` | 同上 |
| **D** | `docs/报告.*`、`docs/汇报.*`、`outputs/d/` | 同上 |
| **A** | `data/`、`scripts/`、`README.md` | 别人的图和报告 |

三条硬规矩：

1. **`data/` 是只读的。** 觉得数据不对、缺字段，群里说，A 改完统一推。谁改 `data/` 谁负责把自己那份恢复回去。
2. **中间产物放 `outputs/<你的字母>/`。** 试画的第 3 版、算废的 CSV，都扔这儿。`figures/` 只放准备进报告的定稿。
3. **文件名按约定取**（见上表），别用 `最终版`、`最终版2`、`真的最终版`。

---

## 5. 每次开工前，先同步 A 的新数据（10 秒）

A 可能在你干活期间补了字段（比如 `movie_details.csv`）。同步一次：

**Branch 菜单 → Merge into current branch…** → 列表里选 **origin/main** → **Merge into feat/b**。

- 菜单里没有 **Merge into current branch**？先点 **Fetch origin**，再打开这个菜单。
- 弹窗说 "Already up to date" 就是已经最新，直接干活。
- **绝对不要点 "Discard changes"**，那个会把你没提交的改动扔掉。

## 6. A 怎么合并（每次 1 分钟）

1. 网页进仓库 → **Pull requests** → 点开队友的那条
2. **Files changed** 扫一眼：只动了他自己的文件？图能点开？没有 `data/`？
3. 点 **Review changes → Approve**（保护规则要求 1 个批准，只有你能批）
4. 点 **Merge pull request → Create a merge commit**（**别用 Squash**，理由见下）
5. **不用删分支**，队友下一轮还要接着用

**为什么必须用 "Create a merge commit"**：它会把 main 的最新状态合回队友的分支，
这样队友下次推的时候不会遇到 "This branch is out of date"。用 Squash 的话历史是干净的，
但队友的分支会一直显示落后，每轮都要手动同步一次，对不熟 Git 的人是额外负担。

**合并顺序**：先 B 的图 1 → 再 C 的图 2 / 图 4 → 最后 D 的报告。报告要引用前四张图，
最后合才不会反复改。

## 7. 不想装 Desktop 的两条路

### 7.1 网页直接传（零安装，适合改文档、传一张图）

1. 打开仓库 → 左上角分支下拉框（默认显示 `main`）→ 选 `feat/b`
2. **Add file → Upload files** → 把文件拖进去
3. 底下 **Commit changes** 直接提交到 `feat/b`
4. 回仓库首页，黄条 **Compare & pull request** → 建 PR

限制：只能传文件、改文本，**不能跑 Python**。要出图还是得本地跑。

### 7.2 只想要 CSV 不想要海报（终端一条命令，26 MB / 3 秒）

```bash
git clone --filter=blob:none --no-checkout https://github.com/Leo-luxy/poster-palette.git
cd poster-palette
git sparse-checkout set --no-cone '/*' '!/data/posters'
git checkout feat/b
```

海报看图就上网页点，干活用这份轻的。**这套只能用命令行**，Desktop 不支持稀疏检出。

## 8. 出问题先看这张表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| push 报 `protected branch hook declined` | 你在 main 上提交 | 切回 `feat/b`，重新 commit + push |
| push 报 `Authentication failed` | Desktop 掉登录了 | File → Options → Accounts → 重新 Sign in |
| push 报 `Updates were rejected` | 你的分支落后了 | Branch → Merge into current branch → origin/main |
| 出现 `Conflicts` 红字 | 你改了别人的文件 | **别自己解决**，群里说一声，A 来处理 |
| Desktop 里 Changes 一片红，全是没改过的文件 | 行尾符 / 权限位变化 | 别提交，先问 A |
| 想看/撤销自己上次提交 | — | History 标签 → 右键那条 → **Revert changes in commit** |
| 克隆卡在 90% 很久 | 海报多、网速慢 | 等，或改用 7.2 的稀疏克隆 |

- [ ] 这次要改的文件，在不在第 4 节「只改这些」里
