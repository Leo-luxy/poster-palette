# 协作流程：直接推 main，只有 `data/` 是只读的

> 三个人都可以直接往 `main` 推，不用建分支、不用提 PR、不用等谁批准。
> 唯一不能碰的是 `data/`——数据是所有人的输入，一个人改了，另外三个人的图会跟着变。
> 全文没有命令要背，需要点的地方都写成了「点哪里」。

---

## 0. 一句话版本

```
main      大家直接推（禁强推、禁删分支，别的不管）
data/     只读，谁改谁负责恢复
```

推之前先点一下 **Pull origin**，推完就完事。

## 1. 哪些文件能改，哪些不能

| 目录 / 文件 | 谁可以改 | 说明 |
| --- | --- | --- |
| `figures/` | B、C、D | 定稿图，文件名按下方约定 |
| `outputs/b/` | B | 你的中间产物、试画版本 |
| `outputs/c/` | C | 同上 |
| `outputs/d/` | D | 同上 |
| `docs/报告.*`、`docs/汇报.*` | D | 报告和 PPT |
| `README.md`、`docs/协作流程.md` | A | 说明性文档 |
| **`data/`** | **只有 A** | 元数据、配色特征、海报、聚合表 |
| **`scripts/`** | **只有 A** | 统一口径在这里，改了对不上 |

按人分：

| 人 | 自己那份 |
| --- | --- |
| **B** | `figures/fig_q1_*.png`、`outputs/b/` |
| **C** | `figures/fig_q2_*.png`、`figures/fig_q4_*.png`、`outputs/c/` |
| **D** | `docs/报告.*`、`docs/汇报.*`、`outputs/d/` |

**文件名是唯一的约定**，别用「最终版」「最终版2」。文件名不撞，Git 就永远不会冲突。

## 2. 一次性准备（A 做）

网页进仓库 → **Settings** → 左侧 **Collaborators**（有的界面在 **Access → Collaborators**）
→ **Add people** → 输 GitHub 用户名 → **Add**。

三人收到邮件后**必须点 Accept invitation**，否则只能看、不能推。

> 仓库是公开的，协作者人数没有上限。公开 ≠ 谁都能推：没被邀请的人只能读。

## 3. 队友要做的：五步，之后一直重复第四、五步

### 第 0 步：有 GitHub 账号（已有就跳过）

没有就去 <https://github.com/signup> 注册，然后把用户名发给 A。

### 第 1 步：接受邀请

邮件里点 **Accept invitation**；或者直接打开仓库链接，页面顶部有绿色按钮。

### 第 2 步：装 GitHub Desktop 并登录

<https://desktop.github.com> → 安装 → 打开 → **Sign in to GitHub.com** → 浏览器授权。

### 第 3 步：克隆到本地（8–12 分钟，只有这一次）

**File → Clone repository → URL**，粘：

```
https://github.com/Leo-luxy/poster-palette.git
```

选个你找得到的位置 → **Clone**。

⚠️ 仓库带 14,657 张海报（716 MB），这一步慢是正常的，进度条卡住别关。
以后再同步只拉几十 KB。

### 第 4 步：先 Pull，再干活

顶部 **Current Branch** 确认显示的是 **main**（不用切别的分支）。

点 **Fetch origin**，如果有新提交，按钮会变成 **Pull origin**，点它。
**每次开始干活前先做这一下**，能省掉 90% 的推送失败。

### 第 5 步：改 → Commit → Push

1. 干活，改动自动出现在左侧 **Changes**
2. 左下角 **Summary** 写一句人话（`图1 色相分布初稿`）
3. 点 **Commit to main**
4. 点顶部 **Push origin**

完事。想改就再重复 3–5。

## 4. 唯一一条日常规矩：推之前先 Pull

Git 的 push 有个硬要求：你本地的 `main` 必须包含远端 `main` 的全部提交。

所以**别人推过之后，你直接推会被拒**，报错长这样：

```
! [rejected]  main -> main (fetch first)
error: failed to push some refs
hint: Updates were rejected because the remote contains work that you do not have locally.
```

**这不是出错，是提醒你落后了。** 处理只要两步：

1. 点 **Pull origin**（Desktop 顶部，或弹窗里直接有这个按钮）
2. 再点一次 **Push origin**

因为大家改的是不同文件，这个 Pull 一定是自动合并、不会冲突。

想彻底不遇到：每次开始干活前先 **Fetch origin → Pull origin**（第 4 步）。

## 5. `data/` 只读是怎么保证的

三道，从软到硬：

| 层 | 机制 | 什么时候起作用 |
| --- | --- | --- |
| 本地钩子 | `.githooks/pre-commit` 拦下带 `data/` 的提交 | 你 commit 的那一刻，直接报错不让你提 |
| CI 检查 | `.github/workflows/data-guard.yml` | 已经推上去了，Actions 里标红，留痕 |
| A 兜底 | A 本地有全量数据，`git checkout` 一条命令恢复 | 真被改坏了，找 A |

**装钩子（每个人一次，10 秒）**：

```bash
cd 你的仓库目录
sh scripts/install_hooks.sh
```

装完再试着提交 `data/`，会被拦下来并告诉你怎么办。A 自己补数据时用
`ALLOW_DATA=1 git commit ...` 或 `git commit --no-verify` 跳过。

**为什么要拦 `data/`**：四个人共用同一份 CSV，谁改了字段、删了行，另外三个人的
图会静默变化——不报错、只是结果不对，这种 bug 最难查。所以数据只有一个人维护。

## 6. 想隔离就用分支（可选，不是必须）

某次改动比较大、想先放着不让人看见，再走分支：

1. **Current Branch → New Branch**，起名 `b-fig1` 之类，基于 `main`
2. 推这条分支：**Push origin**（第一次会问，选 Publish branch）
3. 想合进来时，网页上开 PR，A 点 **Merge pull request → Create a merge commit**
4. 合完在 Desktop 切回 **main**，**Pull origin**

日常小改动不用这么麻烦，直接推 main 就行。

## 7. 出问题先看这张表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `rejected ... (fetch first)` | 别人先推了 | **Pull origin** → 再 **Push origin** |
| commit 被拒，提示 `data/ 是只读的` | 钩子拦住了 | 说明你动了数据文件，`git restore` 撤回，别提交 |
| `Authentication failed` | Desktop 掉登录 | File → Options → Accounts → 重新 Sign in |
| 出现红色 `Conflicts` | 你和别人改了同一个文件 | **别自己解决**，群里说一声，A 来处理 |
| 一片红，全是没改过的文件 | 行尾符 / 权限位变化 | 别提交，先问 A |
| 推错了想撤销 | — | History 标签 → 右键那条 → **Revert changes in commit** → 再推 |
| 克隆卡在 90% 很久 | 海报多、网速慢 | 等；或只想要 CSV 用下面的稀疏克隆 |

只要 CSV 不要海报（终端，26 MB / 几秒）：

```bash
git clone --filter=blob:none --no-checkout https://github.com/Leo-luxy/poster-palette.git
cd poster-palette
git sparse-checkout set --no-cone '/*' '!/data/posters'
git checkout main
```
