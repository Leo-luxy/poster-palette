## 1. 采集口径（要写进报告的方法部分）

| 项 | 值 |
| --- | --- |
| 接口 | TMDB API `/discover/movie`（Developer 免费 key） |
| 筛选 | **每年票数前 2.6%**（不是固定 200 票，见下），`primary_release_date` 在 1950-01-01 至 2025-12-31 |
| 语言 | `language=zh-CN`（所以 `title`、`overview` 是中文） |
| 排序 | `vote_count.desc` |
| 分片 | **按年**分片翻页（`/discover` 的 page 上限 500，不分年最多只能取 1 万部） |
| 海报 | `image.tmdb.org/t/p/w342`，342×512，**原语言版**（见 1.1） |
| 采集时间 | **2026-11-03**（v2） |
| 脚本 | `scripts/01_fetch.py`、`02_check.py`、`03_features.py`、`04_yearly.py`、`06_details.py` |

**为什么不再用固定 200 票**：200 票对 2010s 差不多正好（该年门槛 199），但对 1950s 高了 4 倍（该年门槛 48–72）。
固定阈值会让老片样本变成「前 0.9% 的经典」，新片变成「前 2.6% 的普通片」，比的是两个不同阶层。
改成「每年取票数前 2.6%」后，各年代通过率拉平到 2.6–3.1%（见 `data/quality_report.md` 第 0 节）。

| 1970s | 49–72 | 1,591 | 2.80% |

## 1.1 海报是怎么选出来的

### TMDB 的默认行为

`/discover` 每部片只返回**一个** `poster_path`。它既不是「原版」也不是「最新版」，是服务端按这条规则算出来的：

1. 请求的 `language` 决定**从哪个语种池里挑**（`zh-CN` → 优先 `iso_639_1 = zh`）
2. 该语种没有海报 → **回落到 `original_language` 的池子**（实测 57/57，不是回落到英文）
3. 池子里挑 `vote_average` 最高的那张（实测 86%；剩下 14% 由一个不公开的「主图」标记决定，
   例如有 0 票的图压过 10 分的图）

实测依据：400 部抽样，`outputs/a/poster_sample.csv`。

**v1 的后果**：14,657 张里 41% 是中文版，且比例随年代从 1950s 的 12.5% 涨到 2020s 的 69%
——因为 `language=zh-CN` 是为了拿中文片名/简介，海报是搭便车被中文化的。

### v2 的选图规则

不做「原版」判断（TMDB 没有这个字段，图片也没有日期），只做**去本地化**：

| 优先级 | 条件 | 覆盖 |
| --- | --- | --- |
| 1 | `iso_639_1 == original_language`（原语言版） | 7,724 |
| 2 | `iso_639_1 == null`（无文字版） | 180 |
| 3 | `iso_639_1 == en` | 96 |
| 4 | 都不满足 → 保持 v1 那张 | — |

原本就是原语言/无文字的 11,694 部**不动**（不重下、不重算）。脚本：`probe/plan_orig_posters.py`。

### 三个必须知道的限制

1. **TMDB 没有「海报发行年份」**。`/movie/{id}/images` 的字段只有
   `aspect_ratio / width / height / iso_639_1 / iso_3166_1 / file_path / vote_average / vote_count`，
   没有日期。所以**无法区分首映版和重映版**——这是一个硬约束，不是没做好。
2. **「原语言」不等于「当年那版」**。老片的原语言池里也可能混着修复版、周年重制版。
   已知例子：《仙履奇缘》60 张海报里票最高的英文版是 2012 年 Diamond Edition，
   1950 年原版排在第 5、第 11 位，票数只有 28 和 1。
3. **换图带来的扰动和「同语言换一张」一样大**：`|Δmean_v|` 中位数 0.050，33% 的替换超过 0.10；
   而 1950s→2020s 的明度总变化只有 0.084。也就是说换图主要影响**单片的噪声**，
   对年代均值的影响很小（实测 +0.012，t=0.97）。

### 回退到 v1

`outputs/a/v1_backup/movies_v1.csv` 记着每部片 v1 那张图的原始 `poster_path`，
`probe/restore_v1_posters.py` 按原路径重新下回来即可（约 40 分钟）。

## 3. `color_features.csv` 字段

### 3.1 预处理（所有指标都基于这个版本）

1. 读入海报，转 RGB
2. **裁掉底部 12%**（演职员表、发行方 logo、评分角标）
3. 缩放到 **120×160**
4. 转 HSV，`H∈[0,360)`，`S,V∈[0,1]`
5. 算 **近灰掩膜** `mask = S ≥ 0.20`——只有「有颜色的像素」才参与色相统计

### 3.2 逐字段

| 字段 | 范围 | 怎么算 | 怎么用 |
| --- | --- | --- | --- |
| `mean_s` | 0–1 | 全图 S 的均值 | 饱和度；典型值 0.3–0.6 |
| `mean_v` | 0–1 | 全图 V 的均值 | **区分类型的第一指标**；恐怖 0.38，喜剧 0.63 |
| `v_std` | 0–0.4 | 全图 V 的标准差 | 明暗对比度，高值=暗背景+亮主体 |
| `sat_frac` | 0–1 | `mask` 占全图的比例 | **质量闸门**：< 0.10 说明几乎纯灰，色相不可信 |
| `hue` | 0–360 | 掩膜像素色相的**加权圆均值**（权重=S） | 主色调方向；科幻 ≈200°（青蓝）、恐怖 ≈171° |
| `colorful` | 0–200 | `√(σ_rg²+σ_yb²) + 0.3·√(μ_rg²+μ_yb²)`，`rg=R-G`、`yb=(R+G)/2-B` | Hasler-Süsstrunk 色彩丰富度；家庭/动画 80，惊悚/恐怖 51 |
| `h0`–`h11` | 0–1 | 掩膜像素色相的 12 扇区直方图，**已归一**（和为 1） | 画色相分布图用；`h0`=0–30°（红），`h4`=120–150°（绿），`h7`=210–240°（蓝） |
| `dom1`–`dom3` | HEX | 掩膜像素 K-Means（k=3）的质心 | 报告里展示「这张海报的三个主色」 |
| `ds1`–`ds3` | 0–1 | 对应主色占比 | 与 `dom` 配套 |

### 3.3 三个必须知道的坑

1. **别对 `hue` 直接取算术平均**。角度不能直接平均（350° 和 10° 平均成 180°，实际是 0°）。
   要平均请用 `h0`–`h11` 先转成向量再合成，或者直接对扇区占比做统计。
2. **色相统计前必须过滤 `sat_frac ≥ 0.10`**。622 张几乎纯灰的海报会让色相变成噪声。
   现成函数：`common.usable_hue(df)`。
3. **人脸肤色会污染色相**。三类海报最大色块都是 0–30° 红橙（爱情 34.7%）。
   要谈「主题色」时，建议做一次剔除 10–40° 区间的敏感性分析。

## 5. `movie_details.csv` 字段（逐片详情）

`movies.csv` 是 `/discover` 批量拿的，里面没有生产国家、预算、票房——这些只在单片详情接口里。
所以单独一张表，用 `id` 与主表左连接，`common.load()` 已经自动做了，正常不用手动 merge。

| 字段 | 类型 | 含义 | 注意 |
| --- | --- | --- | --- |
| `id` | int | TMDB id | 与 `movies.csv` 的 `id` 一一对应，19,700 条全覆盖 |
| `production_countries` | 文本 | ISO 两位国家码，`\|` 分隔 | **多国合拍会有多个**，空表示 TMDB 没登记（23 部） |
| `country_names` | 文本 | 国家英文名 | 顺序与上一列一致 |
| `production_companies` | 文本 | 前 3 家制作公司 | 只留 3 家，不能当完整名单用 |
| `budget` | int | 预算，美元 | **0 = 未公开，不是零成本**（9,639 部） |
| `revenue` | int | 票房，美元 | 同上（8,453 部为 0） |
| `runtime` | int | 片长，分钟 | 少量空值 |
| `status` | 文本 | 发行状态 | 本批全部是 `Released`，等于常量，别拿来做分组 |
| `spoken_languages` | 文本 | ISO 语言码 | 与 `original_language` 不同：一部片可以有多语言 |
| `collection_name` | 文本 | 系列名 | 空表示不是系列片 |
| `imdb_id` | 文本 | `tt` 开头 | 要跨库对齐时用 |

**国家分布（19,677 部有记录，共 130 个国家/地区）**

| 国家 | 片数 | 占比 | 国家 | 片数 |
| --- | --- | --- | --- | --- |
| 美国 US | 12,135 | 61.7% | 日本 JP | 921 |
| 法国 FR | 2,730 | 13.9% | 西班牙 ES | 604 |
| 英国 GB | 2,722 | 13.8% | 比利时 BE | 503 |
| 意大利 IT | 1,592 | 8.1% | 香港 HK | 376 |
| 德国 DE | 1,166 | 5.9% | 澳大利亚 AU | 314 |
| 加拿大 CA | 1,013 | 5.1% | 中国大陆 CN | 291 |

**三个坑**

1. **`budget = 0` 是缺失值**。老片几乎全是 0，直接 `budget.mean()` 会得到一个毫无意义的数。
   做 ROI 分析前先 `df[df.budget > 0]`，并在报告里写清筛掉了多少。
2. **合拍片会被重复计数**。按国家统计时一部片同时进「美国」和「英国」，所以各列之和 > 14,657，
   和 `genres` 的多标签问题一模一样。
3. **国家和语言不是一回事**。法国是制片的，语言可能是英语；好莱坞拍的日语片，两者会打架。
   用哪个维度要在报告里说清楚：`production_countries` 是**资方/制片地**，`original_language` 是**原始语言**。
   同一张图里别混着用。

## 6. 已知局限（写进报告的「讨论」部分）

1. **海报不是「当年那版」**。v2 已经去掉中文化（改成原语言版），但 TMDB 没有海报日期，
   「首映版 vs 重映版」无法区分（见 1.1）。老片仍可能混入修复版、周年重制版。
2. **多标签**：一部片可以同时是「科幻 + 动作」，所以各类型样本数之和 > 19,694。
3. **票数门槛仍偏西方/英语片**。改成「每年前 2.6%」后各年代门槛拉平了（48–268），
   但 TMDB 片库本身对非英语、非院线片覆盖不足，这个偏差换门槛解决不了。
4. **明度趋势混了技术因素**：1950s 的海报是手绘石版，2020s 是数字合成，亮度差异不全是审美变化。
5. **2020s 是右删失的**：新片的票数还在涨，今天没过门槛的片子明年可能就过了，
   所以 2020s 那一组的成员每年会变，重跑结果不会完全一致。
6. **简介缺失 8.5%**，做文本选题时要单独处理。

## 7. 复现方式

```bash
cd 大作业
# 1) 逐年算门槛 + 抓片（每年前 2.6%）
python3 probe/era_expand.py                              # 76 年，约 5 分钟
# 2) 查每部片的全部海报，挑原语言版；下图；算特征
python3 probe/plan_orig_posters.py                       # 19,694 次请求，约 45 分钟
python3 probe/download_orig_posters.py                   # 约 20 分钟
python3 scripts/03_features.py                           # 配色特征，WORKERS 可调
# 3) 体检与聚合
python3 scripts/02_check.py                              # 质量报告
python3 scripts/04_yearly.py                             # 年度聚合
python3 scripts/05_fig3_score.py                         # 图 3
python3 scripts/06_details.py                            # 详情表，约 60 分钟
```

`03_features.py` 里每张海报要做一次 K-Means（k=3），很吃 CPU。
机器还要用的时候：

```bash
WORKERS=2 nice -n 19 python3 scripts/03_features.py
```

断点续跑：中断后重跑同一条命令，已完成的年份、已下载的图、已取到的 id 都会自动跳过。
`06_details.py` 带单实例锁，重复开第二个会直接退出——这是防止两个进程同时写同一个 CSV
产生重复行（踩过一次，去重了 453 条）。

> **只有 `01_fetch.py`、`06_details.py`、`probe/` 下几个抓取脚本需要 API key**（找 A，或自己申请一个免费的）。
> 其余脚本都只读本地文件，不需要 key，也不需要联网。
